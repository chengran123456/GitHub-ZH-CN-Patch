# 04 · 验证与排障

汉化这类"看起来变了"的活，最忌讳只看一眼截图就说成功。本节记录**怎么把界面真实文字读回来**，以及踩过的坑。

---

## 1. 核心思路：用 CDP 读，不用眼睛猜

两个应用都是 Chromium 系渲染（Electron / WebView2），只要**临时**打开调试端口，就能用 `document.body.innerText` 读到界面上真正显示的文字。这比截图 OCR 准确，也比"我觉得是中文"可靠。

| 应用 | 端口 | 什么时候开 |
| --- | --- | --- |
| GitHub Copilot 中文版 | 9222 | 启动器每次启动都开（注入器要用） |
| GitHub Desktop | 9223 | **只在验证时**临时开，验完关掉 |

> GitHub Desktop 平时不要带调试端口运行：`--remote-debugging-port` 会让任何本机进程都能读它的页面内容。验证完必须恢复普通启动。

---

## 2. 探针脚本

仓库里 `tools/` 目录下有两个只读脚本（Node 22 自带 `WebSocket`，无需安装依赖）。

### 2.1 `tools/probe-copilot.js`（默认 9222）

```powershell
node tools\probe-copilot.js
```

输出示例：

```
url: http://tauri.localhost/ | title: GitHub Copilot 中文版
visibility: visible | lang: en
--- 界面文本样本 ---
侧边栏
快捷链接
新建
拉取请求
问题
自动化
自定义
项目
暂无项目
...
```

要点：脚本会先 GET `http://127.0.0.1:9222/json` 拿到页面列表，再连上 `webSocketDebuggerUrl`，发 `Runtime.evaluate` 读 `document.body.innerText` 前 900 字符 + 前 25 个按钮/标签的文本。

### 2.2 `tools/probe-desktop.js`（参数化端口）

```powershell
# 1) 临时带调试端口启动
Get-Process GitHubDesktop | Stop-Process -Force
Start-Process "$env:LOCALAPPDATA\GitHubDesktop\GitHubDesktop.exe" -ArgumentList "--remote-debugging-port=9223"
Start-Sleep 12

# 2) 读界面
node tools\probe-desktop.js 9223

# 3) 验完恢复正常启动
Get-Process GitHubDesktop | Stop-Process -Force
Start-Process "$env:LOCALAPPDATA\GitHubDesktop\GitHubDesktop.exe"
```

## 3. 判断"翻够了"的标准

一条文案没翻，通常是三种情况之一，处理方式完全不同：

| 情况 | 判断方法 | 处理 |
| --- | --- | --- |
| 词典里没有这条 | 探针能读到整串英文，且在 `dictionary.json` / `ui-zh.json` 里搜不到 | 加词条（整串作为 key） |
| 这句话是**多个文本节点拼的** | 探针里能看到整句，但用"叶子节点整串"搜不到（见下） | 拆开按**单个文本节点**的词条补，或给渲染层加整句规则 |
| 它被**刻意跳过** | 落在 `<kbd>` / `pre` / `code` / `sr-only` 里 | 不用管（设计如此） |

### 3.1 定位真实文本节点的技巧

探针读到的 `innerText` 是"拼接后的可读文本"，它会把相邻的多个文本节点连成一句。所以会出现这种错觉：

> 探针读到了 `Always available in the toolbar for local repositories or Ctrl+P`，加进词典却不生效。

原因：这一句在后端是 **两个节点** —— `"Always available in the toolbar for local repositories or"` 和 `" Ctrl+P"`（后者在 `<kbd>` 里）。只有前者该翻。用下面这段脚本（`TreeWalker` 走所有文本节点）就能看到真实的节点原文：

```js
(() => {
  const out = {};
  const w = document.createTreeWalker(document.body, NodeFilter.SHOW_TEXT);
  let n;
  while (n = w.nextNode()) {
    const t = n.nodeValue;
    if (!t) continue;
    for (const needle of ['Always available', 'menu or Ctrl']) {
      if (t.includes(needle)) (out[needle] = out[needle] || []).push(JSON.stringify(t));
    }
  }
  return JSON.stringify(out);
})()
```

实测输出：

```json
{"Always available": ["\"Always available in the toolbar for local repositories or\""]}
```

—— 于是词条应该写后者（含末尾空格也算不进 key，渲染层会 trim）。补进去后该句顺利变成中文。

## 5. 本机遇到的问题与真实解法

### 5.1 CU（桌面自动化）授权超时

早期想用 GUI 自动化点开两个应用的设置页。`cu.switch_desktop("main")`（独占用户主桌面）连续两次返回：

```
user authorization for exclusive (main desktop) mode timed out
```

也就是**系统授权弹窗没人点**。于是全程改为"配置文件 + CDP"路线，不再依赖 GUI 点击。

**经验**：这类"改应用显示"的任务，**根本不必要操作 GUI**——GUI 只能证明"我看了一眼"，CDP 能给出"界面上此刻的字符串"。以后遇到同类需求，直接走 CDP。

### 5.2 Electron 关窗口 ≠ 退出

GitHub Desktop 关掉窗口后仍有后台进程；只关窗口，界面不会重新加载到中文。必须：

```powershell
Get-Process GitHubDesktop | Stop-Process -Force
```

### 5.3 Copilot 多个伴生进程

只杀 `github.exe` 不够，`copilotapp` / `copilot-runtime` / `copilotapphost` 会互相拉起。一次性全杀再启动中文版：

```powershell
Get-Process copilotapp,copilot-runtime,copilotapphost,github -ErrorAction SilentlyContinue |
    Stop-Process -Force
```

### 5.4 注入器"抢跑"

注入器比页面先就绪时会打印 `ECONNREFUSED 9222`，然后自己重试；这本就是设计行为，不用管。若持续失败，说明主程序没带调试参数启动（没用启动器）。

### 5.5 `Start-Process -WindowStyle Hidden` 别用在主程序上

验证阶段我用它启动过 `github.exe`，虽然页面 `visibilityState` 仍是 `visible`，但保险起见，正常使用时请让启动器以默认窗口样式拉起主程序——启动器本身只隐藏**命令行窗口**。

### 5.6 没装 Node 时"什么都看不出来"

Node 是两套方案的共同硬性前置：

- GitHub Desktop：`apply.js` 直接报错退出（命令行可见，算好排查）；
- Copilot：`.vbs` 用 `shell.Run "...", 0, False` 以 **0 窗口**方式拉起 `cmd`，找不到 Node 时脚本只是 `exit /b 1` —— **黑框不出现、报错不出现、界面还是英文**，很容易误判成"注入器坏了"。

排查手法：绕开 `.vbs`，直接双击同目录的 `启动 GitHub Copilot 中文版.cmd`，命令行窗口会露出来，`'node' 不是内部或外部命令` 或 `exit 1` 一眼可见。

### 5.7 目录里混进第二个 `.cmd`

`启动 GitHub Copilot 中文版.vbs` 的取法是：

```vb
For Each file In fso.GetFolder(fso.GetParentFolderName(WScript.ScriptFullName)).Files
  If LCase(fso.GetExtensionName(file.Name)) = "cmd" Then
    launcher = file.Path
    Exit For        ' ← 取第一个就退出循环
```

也就是说**它不认文件名，只认"第一个 `.cmd`"**。如果为了测试往里放了 `test.cmd`、`debug.bat`（扩展名 bat 不影响，但 cmd 会抢位），就可能调到错误的脚本，表现为"点快捷方式没反应"或"启动了但没注入"。保持该目录只有一个自带 `.cmd` 是最省事的做法。

## 6. 一键体检清单

```powershell
# 1) GitHub Desktop 补丁文件是否在
Test-Path "$env:LOCALAPPDATA\GitHubDesktop\app-3.6.11\resources\app\zh-cn\renderer.js"
# 2) 注入点是否有且仅有 1 处
Select-String -LiteralPath "$env:LOCALAPPDATA\GitHubDesktop\app-3.6.11\resources\app\main.js" -Pattern 'zh-cn/menu\.js' -AllMatches | Measure-Object
# 3) 备份是否完好
Test-Path "$env:LOCALAPPDATA\GitHubDesktop\zh-cn-backup\app-3.6.11\main.js"
# 4) Copilot 中文版目录与相对路径
Test-Path "$env:LOCALAPPDATA\Programs\GitHub Copilot\GitHub Copilot 中文运行版\..\github.exe"
# 5) 注入器最近日志
Get-Content "$env:LOCALAPPDATA\Programs\GitHub Copilot\GitHub Copilot 中文运行版\cache\injector.log" -Tail 5
# 6) Node 是否可用（两套方案共同前置）
node --version; Test-Path "$env:ProgramFiles\nodejs\node.exe"
# 7) Copilot 中文版目录里是否只有一个 .cmd
(Get-ChildItem "$env:LOCALAPPDATA\Programs\GitHub Copilot\GitHub Copilot 中文运行版" -Filter *.cmd | Measure-Object).Count
```
