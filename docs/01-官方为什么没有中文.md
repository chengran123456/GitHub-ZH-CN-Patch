# 01 · 官方为什么没有中文

这一节记录"官方到底有没有中文界面"的取证过程。结论先给：**网页端、GitHub Desktop、GitHub Copilot 桌面版三者都没有官方中文界面**，而且不是"藏在设置里"，是根本没有中文资源文件。

---

## 1. 网页端（github.com）

### 1.1 时间线

| 时间 | 事件 |
| --- | --- |
| 2010 | GitHub 上线多语言界面（含简体中文） |
| 2016-11-18 | 官方公告：GitHub no longer supports languages other than English —— 除英语外的界面语言下架 |
| 2016 至今 | `github.blog` 的 changelog 里再没有"界面本地化"的相关公告 |

也就是说，网上流传的"Settings → Appearance → Preferred language → 简体中文"是**编造的**：Appearance 页只有主题（light / dark / system）和标签宽度之类的选项，没有语言项。

### 1.2 官方中文只存在于这几个地方

- `docs.github.com/zh` —— 文档站（右上角语言菜单，独立于产品界面）
- GitHub 移动端 App —— 2020 年起支持简体中文
- `support.github.com` —— 支持门户，2022 年起支持多语言
- GitHub Blog 的部分文章

这些都属于"内容翻译"，不是"产品界面本地化"。

---

## 2. GitHub Desktop 3.6.11

### 2.1 静态取证

安装路径：`%LOCALAPPDATA%\GitHubDesktop\app-3.6.11\`，Electron 应用，`resources/app` 是**解包目录**（没有 asar），`webPreferences` 为 `nodeIntegration: true` / `contextIsolation: false`——这为"在 DOM 层翻译"提供了可行性。

关键检查：

```powershell
Select-String -LiteralPath "$env:LOCALAPPDATA\GitHubDesktop\app-3.6.11\resources\app\main.js" -Pattern "language"
Select-String -LiteralPath "$env:LOCALAPPDATA\GitHubDesktop\app-3.6.11\resources\app\renderer.js" -Pattern "language"
```

结果：两个文件各自只有 **1 处** 命中 `language`，而且用途是设置 HTTP 请求头（`Accept-Language`）。**源码里没有任何语言包、语言切换逻辑、i18n 框架**。

### 2.2 一个容易误判的细节

3.6.11 的主窗口 URL 会带一个 `#lc=CN` 片段：

```
file:///.../resources/app/index.html#lc=CN
```

这说明它**已经识别到系统是中文区域**（`lc` = locale），但对应的中文文案并不存在，所以界面仍然是英文。看到 `lc=CN` 就以为"有中文开关"是典型误判——决定界面文字的是有没有中文资源，不是有没有 locale 参数。

**结论：GitHub Desktop 官方无中文，只能外部注入。**

## 3. GitHub Copilot 桌面版 1.4.2

### 3.1 技术栈

安装路径：`%LOCALAPPDATA%\Programs\GitHub Copilot\`

- Tauri + WebView2 原生应用，主程序是单文件 `github.exe`（约 567 MB）
- 同目录还有 `foundry_local.dll`、`onnxruntime*.dll`、`plugins\`（computer-use / excel-agent / powerpoint-agent / word-agent）、`app-extensions\`、`copilot-sdk\`

### 3.2 二进制扫描结果

对 `github.exe` 做字符串扫描（UTF-8 + UTF-16 两种编码都扫）：

| 扫描词 | 命中次数 | 结论 |
| --- | --- | --- |
| `Preferred language` | 0 | 没有"首选语言"设置项 |
| `uiLanguage` / `responseLanguage` | 0 | 没有界面语言键 |
| `zh-CN` | 0 | 没有中文资源标识 |
| `i18next` / `locales` | 0 | 没有 i18n 框架 |
| `简体中文` / `日本語` / `Español` / … | 各 1 次 | 出现在压缩字典数据里，不是语言菜单 |

**结论：`github.exe` 里没有内置多语言资源，界面文案是硬编码英文，只能在运行时注入。**

### 3.3 配置库里有没有语言键

配置库：`%USERPROFILE%\.copilot\data.db`（SQLite，100+ 张表）

- `app_state` 表 26 个键里，只有 `theme-settings-v2`（主题 / 字体缩放 / 终端模式）和 `ui-zoom-level-v2`，**没有任何语言键**；
- `settings` 表有一个 `instructions` 字段（TEXT，"用户指令 / User Instructions"），程序里还有 `SaveAgentInstructions`、`UpdateInstructions`、`UpdateMyCustomProfile` 等消息，提示语是 `Instructions are N bytes; the limit is ...`。

`instructions` 只能影响 **AI 回复的语言**（属于提示词层面），改不了**界面文字**。这一点很关键：

- 想让 Copilot **说中文** → 写 `instructions` 就够了；
- 想让 Copilot **界面变中文** → 必须走 DOM 注入。

本仓库两件事都做了（`instructions` 的写法见 [03](03-GitHub-Copilot-汉化步骤.md) 末尾）。

## 4. 被排除的方案

| 方案 | 为什么不用 |
| --- | --- |
| 早期社区整片替换 `main.js` / `renderer.js` 的汉化包（`lkyero/GitHubDesktop_zh`、`gouzil/github-desktop-zh` 等 2.x / 3.2 时代） | 面向旧版本，直接覆盖整文件；对 3.6.11 会崩，且升级即被覆盖 |
| 伪装系统语言 / 全局 `--lang=zh-CN` | 只影响 WebView2 的 Chromium 语言偏好，应用没有中文文案，界面文字不会变 |
| 修改 `github.exe` 二进制打补丁 | 567 MB 签名二进制，改一处可能破坏签名与 Code signing，且升级即失效，风险远大于收益 |
| 用 UI 自动化去点"设置里的语言项" | 设置里根本不存在这一项 |

---

## 5. 最终路线

- **GitHub Desktop**：静态注入（改 2 个加载点 + DOM 整串精确匹配翻译 + 菜单模板 label 替换）。原理见 [02](02-GitHub-Desktop-汉化步骤.md)。
- **GitHub Copilot**：WebView2 CDP 运行时注入（中文启动器设调试端口 → Node 注入 DOM 翻译器 → 3 秒轮询保活）。原理见 [03](03-GitHub-Copilot-汉化步骤.md)。
