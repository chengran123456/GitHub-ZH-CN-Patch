# 05 · 还原与升级

这个方案的"可逆性"和"升级后会怎样"是最需要提前说清的部分。所有改动都只落在**应用目录 + 用户配置**，没有注册表、没有系统策略（除非你自己加了 WebView2 机器级策略）。

---

## 1. GitHub Desktop

### 1.1 改动清单（只改 2 个文件 + 新增 1 个目录）

| 路径 | 改动 |
| --- | --- |
| `%LOCALAPPDATA%\GitHubDesktop\app-3.6.11\resources\app\main.js` | 头部新增 1 行 `require("./zh-cn/menu.js");` |
| `%LOCALAPPDATA%\GitHubDesktop\app-3.6.11\resources\app\index.html` | `</head>` 前新增 1 行 `<script defer src="zh-cn/renderer.js"></script>` |
| `...\resources\app\zh-cn\` | 新增目录：`menu.js` / `menu-zh.json` / `renderer.js` |
| `%LOCALAPPDATA%\GitHubDesktop\zh-cn-backup\app-3.6.11\` | 新增备份：`main.js` / `index.html` / `manifest.json` |

### 1.2 还原

```powershell
cd github-desktop
node build\restore.js
```

或使用安装脚本自带的卸载开关：

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Uninstall
```

`restore.js` 会按 `manifest.json` 里记录的哈希把 `main.js` / `index.html` 从备份**原样还原**，并删除 `zh-cn\` 目录。还原后重启应用即恢复英文。

### 1.3 升级（Squirrel）

GitHub Desktop 升级会在 `%LOCALAPPDATA%\GitHubDesktop\` 下**新建**一个 `app-X.Y.Z` 目录，旧目录保持不动。所以：

- 升级后**界面会回到英文**（新目录里没有补丁）；
- 处理办法：在 `github-desktop` 目录里重跑一次 `node build\apply.js`——脚本会自动探测最新的 `app-X.Y.Z`，并**只为新版本做首次备份**（不会用已改过的文件覆盖旧备份）；
- 升级到界面结构变化较大的版本时，可能需要补词条（`src\ui-zh.json` / `src\patterns.json`），补完再 `apply.js`。

> 重跑 `apply.js` 不需要先还原：脚本幂等（已注入会跳过），且备份只保留第一次的原件，反复执行不会破坏可还原性。

> 建议把"升级后重跑 apply"写成一个习惯动作。

## 2. GitHub Copilot 桌面版

### 2.1 改动清单

| 路径 | 改动 |
| --- | --- |
| `%LOCALAPPDATA%\Programs\GitHub Copilot\GitHub Copilot 中文运行版\` | **新增**目录（注入器、词典、启动器、日志） |
| `%USERPROFILE%\.copilot\data.db` → `settings.instructions` | 写入 3 行中文回复要求（可由你在应用内改回） |
| `github.exe` / `plugins\` / `*.dll` | **完全未改动** |

也就是说：Copilot 侧**没有修改任何官方文件**，纯新增 + 一处用户配置。

### 2.2 卸载

```powershell
Get-Process copilotapp,copilot-runtime,copilotapphost,github -ErrorAction SilentlyContinue | Stop-Process -Force
Remove-Item "$env:LOCALAPPDATA\Programs\GitHub Copilot\GitHub Copilot 中文运行版" -Recurse -Force
# 桌面快捷方式（如果有）
Remove-Item "$env:USERPROFILE\Desktop\GitHub Copilot 中文版.lnk" -ErrorAction SilentlyContinue
```

删完以后官方图标启动即为纯英文原版。若还想要回 AI 中文回复，把 `settings.instructions` 清空或改成你自己的偏好。

### 2.3 升级

Copilot 升级替换的是 `github.exe` 与周边 DLL，**不会删掉**同级的中文运行版目录。升级后：

1. 重新用中文启动器启动（注入器会连新页面的 9222）；
2. 若新版本界面大幅改版导致覆盖率下降，向 `dictionary.json` 补词条即可（**3 秒热生效**，无需重启）；
3. 若连不上升级后的 WebView2 端口，检查安装程序是否改成需要管理员权限运行（见 [04](04-验证与排障.md) 第 5 节）。

## 4. 卸载顺序建议（如果只想留一个）

1. 先确认哪个用得多：GitHub Desktop 的中文是"装好即用、不用改启动方式"；Copilot 的中文是"必须用启动器"。
2. 停用不想要的那个：按上面 1.2 / 2.2 操作，另一步不动。
3. 两个都留也没冲突：它们各自独立，端口 9222 / 9223 不同、目录不同。

## 5. 安全边界

- 两套脚本我都逐行读过：GitHub Desktop 语言包**没有任何网络请求**；Copilot 注入器唯一的可选外呼是 `gh api` 拉上游词典（本机无 `gh` 时只打警告），**没有上传行为**。
- 调试端口只监听 `127.0.0.1`，局域网不可达；但是**本机其他进程可以访问**，所以 GitHub Desktop 的 9223 只在验证时开、验完就关。
- 不修改签名二进制、不注入系统进程、不改注册表（除你主动加 WebView2 机器级策略）。
